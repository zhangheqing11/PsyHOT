# 重复报道与热度修复（2026-10-21）

## 已确认的原因

在 2026-10-21 01:05 的综合榜上，npj 事件的九条站内记录全部指向小红书笔记 `6ad553df000000001901e400`，仅 `xsec_token` 不同。八条只分析了搜索摘要，一条取得了较完整内容。这不是九篇报道，也不是两家独立来源。

- [npj 事件](https://psyhot.cn/story/81e1fec2-20be-47fa-8a98-4def6c78542e)：九条链接、一个笔记 ID，来自“心理学 新研究”“AI心理健康”两个搜索入口。
- [H.M. 事件](https://psyhot.cn/story/fadc29d7-64ca-479d-bdab-4af42a1dc973)：两条链接都指向 `6ad63c89000000002902e957`，来自不同关键词入口。
- [Fonagy 事件](https://psyhot.cn/story/fca9de6a-0786-45db-9ec6-0667e1a15dd2)：BACP 的 `9-oct-mental-health-support-should-not-depend-on-diagnosis` 与 `9-october-mental-health-support-should-not-depend-on-diagnosis` 指向相同内容。后一次收录被标成 10 月 20 日的新进展，原条目为 10 月 9 日。卫报同日三篇报道的原标题和作者不同，不能按相近标题合并。

旧入口按完整 URL 去重，签名改变便插入新文章并重新付费获取正文、分析和归组。归组把它们放进同一事件，却没有消除物料重复；公开列表只按 article_id 去重。热度本身按 participant_key 分组，并非直接累加九次，但两个搜索入口被记成两个信源，足以让本来未入选的单篇笔记通过上榜条件。重复分析中较高的评分也可能提高事件质量值。

## 排查范围

逐一查看了上述快照综合榜十个事件。榜首光遗传学与 Pla2g2f 事件也有同标题、同时间的小红书重复记录；其余事件保留独立报道，不按标题近似删除。程序修复扫描全库的普通 URL 身份，而不是只修 npj 或当前十条榜单。综合、学界、业界共用重建后的热度证据。

## 修复行为

- 小红书笔记身份取可信主机上的完整 24 位笔记 ID；保留原始带签名链接供访问，搜索入口只记录为发现渠道。
- BACP 日期地址中的月份缩写与全称归一；普通 URL 的路径尾斜线在有查询参数时也正确归一。
- 正文查重与付费正文请求的回执都使用同一身份；搜索摘要不能覆盖已获取的完整正文。
- 全库归并使用和实时入口相同的 URL 规则。保留显式自定义身份与分段页面的 fragment，不按标题、摘要相似度或同一 DOI 猜测合并。
- 优先保留人工限制、人工编辑和较完整内容。原材料、分析和回执不删除；重复项带 `duplicate_of` 标记。发现渠道、事实关联和信源证据合并，旧书签解析至保留项；保留项撤回后，旧书签同样不可见。
- 通过常规发布 projection 和 selected ledger 移除重复项，防止重发或重新归组时复活。
- 相同材料的信源证据取最早观察时间，避免把再次发现旧文当成新报道。撤下污染的综述，排入现有更正任务；重算受影响事件最近七天的小时热度和全部三个榜单。
- 重建检查点保存在数据库中，中断后重跑会继续完成。

## 运行

先备份数据库并停止旧 worker，使用同一版本的代码、API 和 worker：

```bash
node --env-file=.env scripts/migrate.ts
```

正常迁移命令会自动归并历史记录并完成热度重建。Docker 的 setup 已调用该命令。旧 worker 必须停止，因为旧代码不知道新的身份规则。

也可只审计或重跑修复：

```bash
node --env-file=.env scripts/repair-material-identities.ts
node --env-file=.env scripts/repair-material-identities.ts --apply
```

只审计不写入。应用修复不直接调用外部服务，综述重写由现有 worker 的模型预算与回执控制。历史记录仍保留，因此诊断时应区分“原始行数”和“未标记为重复的有效文章数”。

上线后核验：npj 为一条有效报道、一个参与者；未入选时不再靠两个关键词入口上榜；H.M. 不再显示两个独立来源；BACP 不再把十月九日的文章重复列为十月二十日的新进展。再运行只读审计，普通 URL 重复分组应为空。
