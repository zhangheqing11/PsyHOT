# 迭代规划：基于用户标签画像的个性化排序（Jev 相关性判断）

| 项 | 值 |
|---|---|
| 状态 | 规划中，未开工 |
| 记录日期 | 2026-10-01 |
| 目标 | 读者选好身份标签后，在“为你推荐”里优先看到最贴合自己的精选内容 |
| 不在本次范围 | 改变入选门槛、用户账号体系、服务器保存个人数据 |

## 1. 背景与需求

读者选择若干标签，比如“科研工作者 / 社会心理学 / 博士生”，系统用 Jev 判断每条内容和这些身份的相关性，再用算法把最符合的内容排在前面。标签类型由我们设计。

## 2. Jev 是什么，和本项目的契合点

Jev 是 TypeSafe AI 在 2026-09-15 发布的第一个公开模型。创始人 Diogo Almeida 之前在 Google Brain 和 OpenAI 做研究，参与过 ChatGPT 背后的指令跟随工作。下面的信息来自公开报道，**接入前需要用官方文档逐项核实**：

- **不生成文字，只做结构化决策**：输入一段状态（文本或 JSON），加上预先定义好的问题，返回带概率分布和置信度的答案。问题有三种：
  - `Choice`：从最多 255 个预设选项里选一个。
  - `Score`：按评分标准给出连续分数。
  - `Noul`：判断一个陈述是否成立，返回校准过的“是/否”概率。
- **概率是校准过的**：训练方法叫 RLCD（Reinforcement Learning for Calibrated Decisions），目标是“说 70% 把握时，大约 70% 的情况是对的”。
- **快且便宜**：输入每百万 token 0.042 美元，输出免费；延迟 70–500 毫秒；上下文 32K token。
- **局限**：目前需要排队申请早期使用；只支持文本和 JSON；“不会幻觉”是厂商的说法，它仍可能给出格式正确但判断错误的答案；技术细节披露不多。

**为什么适合本项目**：“这条内容和社会心理学研究者有多相关”正是一个有边界的打分问题，不需要生成文字。Jev 返回的是校准过的概率，可以直接参与排序计算，比让大模型输出一个数字再解析更稳定，也便宜几个数量级。

## 3. 可行性结论：可行，但不能“每个用户实时调用”

| 直觉做法 | 问题 | 本规划的做法 |
|---|---|---|
| 读者打开页面时，用 Jev 对他的画像实时判断每条内容 | 违反项目规则“读者打开页面不触发模型调用”（AGENTS.md）；成本随用户数线性增长；每次打开页面都要多等几百毫秒 | 内容入选时，在 worker 里用 Jev 对**每个标签取值**预先打分。标签数量有限，成本只与内容数有关，与用户数无关 |
| 按**信源**判断相关性 | 太粗。同一本期刊会同时发多个方向 | 按**每条内容**判断；信源只作为补充先验 |
| 服务器保存用户画像 | 本站公开内容匿名，读者状态只存在浏览器里（`apps/web/app/lib/local-state.ts`） | 画像存在浏览器，排序在浏览器里计算，服务器对所有人返回相同数据 |
| 只按相关性排序 | 信息茧房；相关但质量差的内容排到前面 | 相关性只调整已入选精选内部的顺序，并设置重大事件保底和探索名额 |

**为什么不能直接对“标签组合”打分**：角色、阶段、领域、议题的组合有上千种，按组合预算不现实。所以对每个**维度取值**单独打分，再在浏览器里按读者的选择组合起来。

## 4. 标签体系

领域和议题直接复用 `industry/taxonomy.ts` 里的 `TOPIC_TAGS`，模型已经给内容打了这些标签，用户侧和内容侧天然对齐。

| 维度 | 选法 | 选项（初稿） |
|---|---|---|
| 角色 | 单选 | 科研工作者、临床与精神科医生、心理咨询师与治疗师、学校与教育工作者、心理健康行业从业者、媒体与科普作者、关注者 |
| 阶段 | 单选，可跳过 | 本科生、硕士生、博士生、博士后与青年教师、资深从业者 |
| 领域 | 多选 1–3 个 | 认知、社会、人格、发展、临床、咨询、健康、生理/神经、进化、组织/管理、教育、司法、积极心理、跨文化、决策 |
| 议题 | 可选多选 | 抑郁、焦虑、创伤/PTSD、成瘾、儿童青少年、老龄化、AI 与心理、开放科学等现有议题标签 |

示例：用户 A = 角色“科研工作者”+ 阶段“博士生”+ 领域“社会”。

## 5. 算法设计

### 5.1 离线：内容入选后，由 worker 用 Jev 打分（每条内容只算一次）

**输入状态**：中文标题、摘要、原文标题与摘要片段、内容类型、标签、信源名，拼成一段 JSON。

**问题集**：在一次调用里并行问完。每条内容约 60 个问题，单次调用能问多少个，需要按官方文档核实；放不下就拆成两三次调用。

| 问题 | 类型 | 产出 |
|---|---|---|
| 这条内容对“{角色}”的工作有多大价值？（7 个角色各问一次） | `Score`，配评分标准 | `p_role[i][角色]` ∈ [0,1] |
| 这条内容的主要贡献属于“{领域}”吗？（每个领域问一次） | `Noul` | `p_field[i][领域]` |
| 这条内容实质讨论了“{议题}”吗？（每个议题问一次） | `Noul` | `p_topic[i][议题]` |
| 读懂并用上这条内容需要的专业深度 | `Choice`：入门 / 进阶 / 专业 | 用来匹配阶段 |

每个答案同时记录置信度 `c ∈ [0,1]`。

**角色评分标准示例**（写进 `industry/prompts/` 的新文件里，便于不改代码就能调整）：
- **对科研工作者有价值**：带来新的研究发现、方法、数据或理论争论，能影响选题、研究设计或对文献的判断。
- **对心理咨询师有价值**：能改变评估、干预、伦理或执业方式，或者涉及从业资质与规范。

**向量兜底**：Jev 置信度低、调用失败，或者服务不可用时，用嵌入向量的相似度代替：

```
p_field[i][t] ≈ sigmoid( (cos(e_i, v_t) − 均值_t) / 标准差_t )
```

其中 `e_i` 是内容向量，`v_t` 是标签描述的向量。项目已有 `embeddings` 表和向量调用代码，可以复用。

**存储**：把这些概率压缩成一个约 60 维的数组，存到 `publications` 的新列 `relevance real[]`（增量迁移），同时存一个模型版本号，方便以后整体重算。

### 5.2 在线：浏览器里计算个人相关度

```
r(i, u) = w_role · 角色分 + w_field · 领域分 + w_topic · 议题分 + w_stage · 深度匹配 + w_tag · 标签精确匹配
初始权重：0.30、0.30、0.15、0.10、0.15
```

- **角色分**：直接用 `p_role[i][读者的角色]`。
- **领域分**：读者所选领域上的最大值加平均值的组合，`0.6·max + 0.4·mean`。这样既奖励“命中一个核心方向”，也照顾“多个方向都沾边”。
- **议题分**：同上，读者没选议题时，这一项的权重分给领域。
- **深度匹配**：阶段和深度的对照表，例如本科生更偏好“入门”和“进阶”，博士生和资深从业者偏好“专业”。
- **标签精确匹配**：内容已带有读者所选的标签，就记 1。这一项最可靠，用来纠正模型偶尔的偏差。
- **按置信度收缩**：每个概率都按置信度向 0.5 收缩，`p' = 0.5 + c · (p − 0.5)`，把握不大的判断不会把排序拉偏。

### 5.3 最终排序

```
最终分 = 质量分 × (0.4 + 0.6 · r) + 热度加成
```

- **乘法的作用**：质量分来自现有的两次独立评分。相关度只能在质量的基础上调整顺序，对口但质量差的内容排不过质量高、稍不对口的内容。
- **重大事件保底**：质量分 ≥ 85 的内容，不管和读者是否相关都留在前列。
- **多样性**：从高到低挑选时，和已选内容过于相似的候选扣分（MMR 方法），相似度用内容向量计算。同一事件的多篇报道已经由聚簇合并。
- **探索名额**：约 10% 的位置留给领域外的高质量内容，标注“你关注领域之外，但值得一看”。

### 5.4 第二阶段：从行为中学习（仍然只在浏览器里）

用本地记录的点开、收藏、跳过，慢慢修正读者的维度权重：经常点开的领域，权重上调；经常跳过的内容类型，权重下调。每次变化设上限，并且读者可以一键重置。所有数据都不离开浏览器。

## 6. 落地到现有架构

| 模块 | 改动 |
|---|---|
| `database/migrations/` | 新迁移：`publications.relevance real[]`、`relevance_version text`；新建标签原型向量表（用于向量兜底） |
| `packages/backend/src/providers/` | 新增 Jev 适配器，同样经过回执（`receipts.ts`）和预算熔断；`.env` 增加 `JEV_API_KEY` 等配置，`MODEL_CALLS_ENABLED` 关闭时一并关闭 |
| `packages/backend/src/editorial/` | 内容入选后加一个 `relevance` 任务；问题集和评分标准放在 `industry/` 里 |
| `packages/backend/src/publication/` | 精选列表接口多返回 `relevance`、内容类型、质量分；所有人数据相同，照常缓存 |
| `apps/web/` | “为你推荐”标签页和画像设置页；画像存在 `local-state.ts`；默认“精选”页不变，不影响搜索引擎收录和分享 |
| `tests/` | Jev 适配器用本地假服务测试，测试不访问外部服务 |

**成本估算**（按公开价格）：每条内容的状态加约 60 个问题，估计 3,000 到 5,000 个输入 token。每天几百条内容，合计约一两百万 token，按 0.042 美元每百万 token 计，一天几美分。实际成本以官方计费方式为准，尤其要确认问题文本是否按次重复计费。

## 7. 风险与待确认事项

| 风险 | 应对 |
|---|---|
| 目前需要排队申请早期使用 | 先申请；拿到之前用向量兜底方案先把前端和排序跑通 |
| **中文支持情况不明** | 拿到权限后先做第 8 节的小规模测试；中文效果不好的话，给 Jev 输入英文原标题和英文摘要 |
| 单次调用最多能问多少个问题未知 | 按官方文档设计分批 |
| 从中国大陆能否访问，数据会发往海外 | 送出的只有公开内容，不含任何读者数据；网络不通时，可以通过 `EGRESS_PROXY_URL` 这类代理，或者部署在海外服务器上 |
| 它仍可能“很有把握地判断错” | 用置信度收缩加上标签精确匹配校正；离线评测要单独看错误案例 |
| 供应商被锁定，或服务停止 | 只把 Jev 的结果存成通用的概率数组，随时可以切换到向量方案或其他模型重算 |

## 8. 验证方案

1. **小规模测试（接入前）**：取 100 条已入选的内容和 5 个典型画像，分别用 Jev 和向量方案打分。和人工标注对比，同时检查中文效果和校准情况（模型说 70% 时，是否大约 70% 对）。
2. **离线评测**：5 到 8 个画像，每个画像请一位真实读者标注 100 条内容的相关度，对比“只按质量分”“向量方案”“Jev 方案”在前 10 条上的排序质量（NDCG@10）。做法沿用 SelectBench 和 `scripts/eval-selection.ts` 的思路。
3. **上线**：先只在“为你推荐”里试用，默认页面不变。

## 10. 顺带的机会（本次不做）

预筛（`industry/prompts/prefilter.md`）本质上是 PASS / BLOCK / UNKNOWN 三选一，正好对应 Jev 的 `Choice`。等个性化跑通、对 Jev 的中文效果有了把握之后，可以用现有的标注样本评估一下，看用它替换预筛能不能降低成本和延迟。
