# 迭代规划：学界 / 业界双视角

| 项 | 值 |
|---|---|
| 状态 | 规划中，未开工 |
| 记录日期 | 2026-10-05 |
| 目标 | 读者可以只看学界、只看业界，或综合起来看；整站（精选、全部动态、热点、主题、日报、RSS、API、MCP）用同一个开关 |
| 不在本次范围 | 用户账号、服务器保存读者偏好、个性化排序（见 `personalization-jev.md`，本规划是它的前置） |

## 1. 背景

PsyHOT 目前几乎只有学界内容。线上近 30 天：进入分析的条目里“行业”类只有 115 条（约 3%），入选 13 条，其中 9 条是 Data Colada 讲科研诚信的旧案，真正的业界内容接近零。61 个信源里 51 个是期刊、学会或学报，没有政策、监管或行业媒体。

学界和业界的传播方式不同，排法也该不同：

| | 学界 | 业界 |
|---|---|---|
| 典型内容 | 期刊论文、预印本、元分析、方法学争论 | 政策法规、执业资质、药物和器械审批、服务机构与产品、AI 心理陪伴的安全与监管、行业调查 |
| 传播 | 通常一本期刊发表，很少有人跟进（30 天内 544/545 个事件只有一个信源） | 一件事常有多家媒体在几天内跟进 |
| 适合的热度 | 质量排序 | AIHOT 原来的多源热度 |

## 2. 核心决定：“视角”由类别推出，不新增模型字段

每个类别归属一个视角，写在 `industry/taxonomy.ts` 里：

```ts
export const TRACKS = [
  { key: "academic", label: "学界" },
  { key: "industry", label: "业界" },
] as const;

export const CATEGORIES = [
  { key: "research", track: "academic", … },
  { key: "review",   track: "academic", … },
  { key: "clinical", track: "academic", … },
  { key: "method",   track: "academic", … },   // guide 加上“科研诚信与撤稿”
  { key: "opinion",  track: "academic", … },
  { key: "policy",   track: "industry", label: "政策", section: "政策与监管", … },  // 新增
  { key: "industry", track: "industry", label: "行业", section: "行业与服务", … },  // guide 收窄为服务、产品与市场
] as const;
```

为什么这样定：

| 备选 | 问题 |
|---|---|
| 按信源划分 | PsyPost、KFF、APA、Retraction Watch 这些源两边都发；业界媒体报道一项研究时，那条应该算学界 |
| 让模型另判一个“视角”字段 | 要改提示词、加迁移、重跑历史数据；类别已经表达了同样的信息 |
| **由类别推出（采用）** | 不加数据库列，筛选就是 `p.category = ANY(…)`；类别 key 只增不改，符合 taxonomy.ts 的约定 |

调整说明：
- 新增 `policy` 类。`industry` 的 key 不变（网址里已经在用），只收窄 guide 的说明。科研诚信移到 `method`（“开放科学与科研诚信”），归学界。
- 历史数据：类别是 `industry`、第一个标签是“科研诚信”的条目，一次性脚本改成 `method`。其余历史条目不动。
- 没有类别的条目（未入选的部分）只出现在“综合”视角里。

## 3. 读者怎么选

- 开关有三档：**综合 / 学界 / 业界**，默认是综合。桌面端放在页面标题旁、类别栏上方；手机端放在顶栏下面。
- **网址是唯一的真实状态**：`?track=academic|industry`，不带参数就是综合。服务端渲染、缓存（`s-maxage`）和分享链接都按网址走，不按 Cookie 分流。
- **偏好记在浏览器里**：`local-state.ts` 新增 `aihot-track` 键。读者切换后，站内链接都带上 `track`。直接打开不带参数的首页时，如果本地记着偏好，就在客户端用 `replace` 跳到带参数的地址（只多一次请求，不涉及隐私，服务器不保存任何东西）。
- 类别栏跟着视角变：选了学界只显示 5 个学界类别，选了业界只显示政策和行业。网址里的 `category` 和 `track` 冲突时，以 `category` 为准。
- 综合视角下，业界卡片的类别角标换一个色调，方便区分。不加新的徽章。

## 4. 各个出口怎么改

所有公开出口都从 `packages/backend/src/publication/` 读，所以只在这一层加一个条件：

```ts
// items.ts，挨着 categoryCondition
export function trackCondition(track: TrackKey | null | undefined) {
  if (!track) return sql``;
  return sql`AND p.category = ANY(${TRACK_CATEGORIES[track]})`;
}
```

| 出口 | 改法 |
|---|---|
| 精选时间线、全部动态、主题页 | 接口加 `track` 参数，查询加 `trackCondition`。时间线按时间排序，混排不存在谁压过谁的问题 |
| 热点榜 | 见第 5 节 |
| 日报、周报、月报 | 见第 6 节 |
| RSS | 新增 `/feed/track/academic.xml`、`/feed/track/industry.xml`（以及对应的 full 版本），写法同分类订阅 |
| 公开 API v1、MCP | 加可选参数 `track`，不传时行为和现在完全一样（向后兼容） |
| 邮件日报 | 订阅时可选视角：`email_subscriptions` 加一列 `track`，默认空表示综合。功能还没上线，现在加最省事 |

## 5. 热点榜：一次计算，三份榜单

`events/hot.ts` 的 `computeHotRanking` 现在取前 10 条就停。改成：

1. 候选同样按热度排序，每个事件的视角取代表文章的类别。
2. 分别取学界前 10、业界前 10、综合前 10，合在同一行 `hot_rankings.entries` 里。每条记录带上 `track`，以及它在各自榜单里的名次（`rank`、`rankInTrack`）。不需要加数据库列。
3. 两个视角的排法不同：
   - **学界**：质量排序，就是上一轮说的“本周值得读”。每个信源最多 2 条，子领域尽量分散。
   - **业界**：沿用多源热度，“质量 × 独立参与方数”。这里多源真的会出现。
4. **综合榜**：两边热度的量纲不同，业界的多源事件会把学界全部挤掉。所以综合榜保证每个视角至少有 3 个名额（某一边不够时让给另一边），其余按各自榜内名次交替填入。

页面上的热度说明（`llms.ts` 和热点页的文案）按视角分别写清楚。

## 6. 日报：一份报告，按视角分组

- 每天还是只出一份报告，不增加成刊次数。分节按视角排：先学界各节，再业界各节（`reports/compose.ts` 的 `SECTION_ORDER` 按 `CATEGORIES` 顺序生成，taxonomy 里的顺序排好即可）。
- 导语（`report-daily-lead.md`）改成结构化输出 `{ academic, industry }` 两段，还是一次模型调用。综合视角两段都显示；只看某一边时只显示对应的一段，并隐藏另一边的分节。
- 某个视角当天没有入选内容时，那一段导语留空，分节也不出现。
- 周报、月报同样处理。

## 7. 前置条件：先有业界内容，再上开关

现在业界一个月只有十几条入选。开关如果先上线，读者切到“业界”看到的基本是空页面。所以顺序是：

1. **站长定信源**：国内、国际都要（已确认）。候选清单和香港服务器的测试结果见 `industry-sources.md`。
2. 评分提示词补充业界的“重要”和“噪声”例子（培训和证书营销、公司公关稿、小额融资快讯、名人八卦算噪声）；涉及具体从业者的伦理事件，以官方通报或法院文书为准。
3. 业界信源跑 1–2 周，用你标注的业界样本校准门槛（`docs/selection.md`），不凭感觉改数字。
4. 业界每周稳定有大约 10 条以上入选，再打开读者可见的开关。

开关用 `industry/features.ts` 里的 `tracks` 控制：关闭时网站和现在完全一样，后端参数照常可用。

## 8. 分阶段计划

| 阶段 | 内容 | 读者可见 |
|---|---|---|
| 0 | 业界信源、新增 `policy` 类、提示词、历史条目重新归类、门槛校准 | 只是多了业界内容 |
| 1 | taxonomy 加 `track`；publication 层加 `trackCondition`；时间线、全部动态、主题、RSS、API、MCP 支持 `track`；测试 | 否（功能开关关着） |
| 2 | 热点榜三份榜单；学界质量排序和单信源上限 | 否 |
| 3 | 日报分组、两段导语；邮件订阅的视角选项 | 否 |
| 4 | 网页开关、本地偏好、类别栏联动；打开 `FEATURES.tracks`；写更新日志 | 是 |

每个阶段都跑 AGENTS.md 规定的检查（typecheck、测试库上的 `npm test`、web 构建和测试、smoke）。

## 9. 验证

- 单元测试：`trackCondition` 和类别的对应关系；三份热点榜的名额规则（某一边不足 3 条时的让位）；`track` 和 `category` 冲突时的处理。
- 接口测试：不传 `track` 时，API、RSS、MCP 的输出和改动前逐字节一致。
- 上线后：访问统计按 `track` 参数看三档各自的使用比例，用来决定默认档要不要换。

## 10. 已确认（2026-10-05）

1. 默认档：综合。
2. 新类别：“政策”（政策与监管）和“行业”（行业与服务）。
3. 综合热点榜每个视角保底 3 个名额。
4. 业界国内、国际都要。信源候选和测试结果见 `industry-sources.md`，等站长挑选。
