# 公众号页面实施计划（本地阶段）

日期：2026-10-25
目标 checkout：`AIHOT-sources`
目标分支：`feature/wechat-requested-accounts`

## 目标

在桌面侧边栏“内容”分组中，把“公众号”放在“心理学日报”和“主题”之间，新增一个 `/wechat` 页面。页面展示已核验固定公众号产生的所有公开文章，不增加账号筛选，不接入生产服务器。

第一阶段只建立稳定的公众号来源范围和本地浏览入口，不把现有全站的学界、业界、内容分类或领域标签当作公众号的最终 taxonomy。待本地积累并提取公众号文章后，单独做集中分析，再决定哪些标签复用、哪些新建。

## 已确定的产品边界

- 来源范围：`sources.kind = 'mp_account'`，只包含已核验并作为固定信源启用的公众号。
- 内容范围：所有符合公开读取规则的公众号文章；文章可以带“精选”状态，但页面默认不只展示精选。
- 首版不做：账号筛选、任意关键词公众号文章流、生产部署、生产数据库改动、公众号专属日报、公众号专属 RSS/API、现有 taxonomy 的直接复用。
- 页面首版保留：标题、摘要、原文链接、发布时间、来源公众号、搜索、分页、已读和收藏等既有文章能力。
- 分类显示：第一阶段不显示或不提供现有学界/业界/领域筛选，避免在集中分析前把旧分类当成最终结论。现有文章内部已有的结构化字段只用于后续分析，不作为本阶段产品承诺。
- 数据获取：固定账号采集继续走现有 EveryInfra / WeChat 付费回执、预算和身份核验链路；账号发现结果必须经过人工核验后才进入页面。

## 依赖关系

```text
现有 mp_account 数据与公开读取规则
    -> source=wechat 内部过滤契约
        -> /wechat 后端页面接口
            -> 公众号页面与侧边栏入口
                -> 本地 corpus 导出
                    -> 集中分析与 taxonomy 提案
                        -> 用户确认后再接入分类/标签筛选
```

## 任务拆解

### Phase 0：本地基线和范围护栏

**描述：** 固定实现 checkout，确认只在本地工作；建立代码、数据库和运行边界，避免误触生产。

**验收条件：**

- [ ] 实现在 `AIHOT-sources` 的 `feature/wechat-requested-accounts` 分支。
- [ ] `git status`、目标数据库和本地服务地址在记录中可追溯。
- [ ] 不执行 SSH、生产数据库写入、生产镜像构建、部署、push 或 merge。
- [ ] 付费采集和模型调用默认保持关闭；本阶段不为页面实现购买新的公众号数据。

**验证：**

- [ ] 记录当前分支、HEAD、工作区状态和本地数据库名称。
- [ ] 运行前确认 `COLLECT_ENABLED=false`、`MODEL_CALLS_ENABLED=false`，并在结果中区分“已有本地数据”和“本次新采集”。

**依赖：** 无。

**预计范围：** XS，配置和记录，不改业务代码。

**验收条件：**

- [ ] 无 `source` 参数时，全站 `/`、`/all`、现有 API 行为不变。

- [ ] 公开读取层继续统一执行 `visibility`、`eligible`、发布延迟和现有推广规则。
- [ ] 不新增 `CATEGORIES`、`TOPIC_TAGS`、数据库迁移或新的文章分类字段。

**验证：**

- [ ] 增加后端测试：公众号、RSS、网页、X 和外部推送混合数据下，范围只保留 `mp_account`。

- [ ] `/wechat` 默认展示所有公开 `mp_account` 文章，并显示来源、时间、标题、摘要和精选状态。
- [ ] 首版没有账号下拉筛选。
- [ ] 支持标题、摘要和可公开检索正文的搜索，搜索结果仍限定在公众号范围内。

- [ ] 点击页面中的文章分类或标签时，若这些链接保留，必须继续带有公众号范围；不能无意跳到全站全部动态。

- [ ] 页面不展示现有学界/业界/领域筛选栏，也不把旧标签包装为公众号最终分类。

### Checkpoint A：本地页面确认

在进入文章集中分析前，先让用户在本地确认：

- [ ] 入口位置和页面名称。
- [ ] 页面展示“所有公开文章”的密度和排序。
- [ ] 搜索、分页、详情、收藏和已读是否符合预期。
- [ ] 是否确实暂不显示旧的学界/业界/领域筛选。

未经这个 checkpoint 确认，不增加 taxonomy 相关代码。

### Phase 3：本地公众号文章提取与数据质量盘点

**描述：** 在本地只读导出已存在的公众号文章，形成集中分析输入。导出服务于本地分析，不作为网站公开文件，也不提交包含文章正文的产物。

**验收条件：**

- [ ] 只读取 `mp_account` 文章和必要的来源、发布时间、标题、摘要、正文可用性、精选状态、现有结构化字段。
- [ ] 输出按文章去重，不重复计算同一文章的 revision。
- [ ] 统计每个公众号的文章数、时间覆盖、正文可用率、分析完成率、精选率和空字段比例。
- [ ] 标记待核验账号、身份不符、采集失败、只有标题、正文缺失等数据缺口。
- [ ] 导出文件保存在本地临时目录或 `.data/`，不放入公开静态目录，不提交到 Git，不上传外部服务。
- [ ] 本阶段不触发 EveryInfra 付费调用，不触发模型调用。

**可能涉及文件：**

- 新增一个本地只读导出脚本，例如 `scripts/export-wechat-corpus.ts`。
- 新增一份本地分析说明，例如 `docs/plans/wechat-corpus-inventory-2026-10-25.md`。

**验证：**

- [ ] 导出前后核对数据库文章总数和去重数量。
- [ ] 用 SQL 和脚本各抽样核对来源类型、文章 URL、日期和状态。
- [ ] 明确报告“本地已有数据量”和“本次未采集的数据”，不把配置数量当成采集成功数量。

**依赖：** Phase 2 的本地页面完成；需要本地数据库中有可读取的公众号数据。

**预计范围：** S–M，脚本和分析记录；不改线上数据。

### Phase 4：集中分析与 taxonomy 提案

**描述：** 基于本地公众号文章 corpus，先观察实际内容分布，再提出公众号专用或可复用的标签方案。

**验收条件：**

- [ ] 按公众号、时间和文章主题做覆盖盘点，识别重复栏目、稳定主题、营销/课程/招聘噪声和长期缺失领域。
- [ ] 现有学界/业界/领域标签只作为对照变量，不直接视为正确答案。
- [ ] 形成候选标签表：标签名、定义、正例、反例、适用公众号、覆盖比例、是否建议复用现有标签。
- [ ] 区分“文章内容标签”和“来源账号标签”，不把来源类型混入内容 taxonomy。
- [ ] 对低频、没有真实样本支持的标签标记为暂缓，不为凑齐分类而保留。
- [ ] 输出一份需要用户确认的 taxonomy 提案，之后再决定是否接入页面筛选、卡片标签、日报或 API。

**验证：**

- [ ] 至少抽查一批真实文章，逐条确认标签定义是否能区分内容。
- [ ] 报告中列出样本量、覆盖范围、缺失数据和不确定项。
- [ ] 不以模型一次性输出或静态配置数量作为最终分类证据。

**依赖：** Phase 3。

**预计范围：** M–L，取决于本地公众号文章数量；仍不改生产。

### Checkpoint B：taxonomy 方案确认

用户确认以下内容后，才进入后续实现：

- [ ] 哪些标签是公众号页面首版需要的。
- [ ] 哪些标签可以复用全站 taxonomy。
- [ ] 哪些标签需要公众号专用。
- [ ] 是否需要把视角、地区、内容分类加入筛选栏。
- [ ] 是否需要把这套标签同步到日报、RSS、API 或 MCP。

### Phase 5：可选的分类接入（本计划暂不执行）

只有 Checkpoint B 通过后，才拆出独立任务：

- [ ] 将确认后的标签写入稳定的 taxonomy 配置。
- [ ] 为公众号页增加筛选和标签展示。
- [ ] 为模型内容理解和标签规范增加同步规则。
- [ ] 建立标注样本和回归测试。
- [ ] 再讨论是否影响日报、热点榜、RSS、API、MCP 和 Agent。

## 总体验收标准

- [ ] 本地 `/wechat` 可访问并只显示已核验固定公众号的公开文章。
- [ ] 页面展示的是所有公开文章，不要求精选才能出现。
- [ ] 首版没有账号筛选。
- [ ] 首版不承诺复用现有学界/业界/领域 taxonomy。
- [ ] 非公众号页面行为不变。
- [ ] 生产服务器、生产数据库、生产容器和远程 Git 均未被修改。
- [ ] 所有状态区分为“本地已验证”“配置存在”“数据缺失”或“尚未验证”。

## 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| 公众号账号配置存在但身份未核验 | 页面没有真实文章或混入错误账号 | 只允许 `wechatBiz` / `ghid` 核验后的 `mp_account` 进入页面 |
| 付费列表和正文调用成本不同 | 批量补历史文章可能产生额外费用 | Phase 3 只分析已有本地数据；任何新采集单独确认预算 |
| 旧标签与公众号实际内容不匹配 | 读者误以为分类已经成熟 | 首版隐藏旧 taxonomy，集中分析后再决定复用 |
| 来源过滤遗漏缓存键 | 页面之间出现串数据 | 将 source scope 纳入查询绑定、count cache 和分页游标 |
| 文章正文版权和敏感信息 | 本地数据外泄 | corpus 只存本地临时目录，默认不提交、不上传、不放静态目录 |
| 公众号文章数量不足 | taxonomy 结论不稳 | 报告覆盖量和缺口，必要时先扩充已核验固定账号再分析 |
