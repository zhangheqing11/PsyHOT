# X 事件反查：先验证查询格式

对应 `交接-2026-10-24-X事件反查热度.md` 的试探阶段。正式任务 `hot.x-lookup` 要等真实试搜结果交给站长、确定格式后再接入。

当前交付是一个运维脚本：从最新已发布热点榜三个列表按名次交错取最多 10 个不同事件，从其公开报道提取 DOI、原文链接、英文原标题中的连续 6–8 词短语，分别搜索。不存在的格式跳过，不造关键词。DOI 优先从报道地址提取，正文中的 DOI 仅作后备，人工复核时尤其要检查它是否只是参考文献。

脚本只读事件和报道；付费调用仍写标准回执与 attempts，不入库推文、不写热度记录、不调用模型。

## 运行

在含本分支代码、已迁移的应用环境里执行。没有 `--run` 时只生成/预览固定样本，不收费：

```bash
node --env-file=.env scripts/probe-x-story-lookup.ts --plan .data/x-story-probe-2026-10-24.json
node --env-file=.env scripts/probe-x-story-lookup.ts --plan .data/x-story-probe-2026-10-24.json --run
```

Docker 环境不要给运行中的容器直接覆盖程序。可在独立 checkout 构建临时镜像，仅运行本脚本，或把本分支合入后的应用镜像用于试探。这里只做试探，不提前套用正式上线的迁移/停信源操作。

- 计划文件冻结事件、报道、截止时间和查询格式。续跑用同一个计划文件，成功的回执会复用；不要为了越过限额重新生成计划。
- 每个计划最多 30 次实际 attempts（包括失败）；同一计划的并发进程由数据库会话锁互斥。到上限后只允许回读已有成功回执。
- 总预算和 `everyinfra:twitter` 份额照现状执行，均不提高。当前 X 每日份额 15，可能分两天或更久完成，取决于现有信源占用。
- 预算用完会保存进度并正常结束。未知结果或其他错误停止，不自动重发。恢复先检查回执状态。
- `--run` 需要事先存在的计划，避免误触时自动选样并付费。
- 结果写到 `<计划文件>.results.json`，每次查询后原子保存；重跑会重建该文件。人工填写应保存在另一个副本。
- 计划和结果包含公开报道/推文正文，只保存在 `.data/`，不提交 Git。

## 三种格式与人工复核

| 格式 | 示例查询主体 | 确定性规则 |
|---|---|---|
| DOI | `10.1038/…` | 正文或显式链接中的 DOI 完全相同，忽略大小写 |
| 原文链接 | `url:nature.com/articles/…` | 实际链接的主机、路径一致；去掉协议、查询参数和追踪参数 |
| 英文短语 | `"sleep changes emotional memory across human adolescence"` | 正文含完整连续词组，忽略大小写、标点及空白差异 |

每种查询附 `since:<7 天前>` 和 `-filter:replies`。仍逐条拒绝没有可信时间、窗口外、未来时间、错误推文 ID 或不安全推文地址的结果。既有 `everyInfraXCandidate` 负责身份和互动数规范化。

短语从原文连续截取，不删除中间词而拼接不存在的句子；泛词不作短语的开头/结尾。仅有根地址、靠查询参数区分的公众号地址等不用于 URL 检索。短链不额外请求展开，服务商没有提供展开链接时宁可漏掉。

结果中：

- `received`：服务商返回的原始条数。
- `matched`：通过精确证据与时间/身份检查的不同推文数。
- `selected`：按点赞 + 2×转发 + 回复选择的最多 5 条。
- `samples`：有效推文地址、正文、互动值、规则命中情况、是否在前 5，以及默认 `null` 的人工 `review`。不安全地址不会作为样本显示，完整原始响应仍在回执。
- `receiptCostUsd`：回执记录的费用；`newCostUsd`：本次新费用，复用为 0，服务商未报告则为 null。

人工逐帖判断它是否在讨论对应事件，分别汇总三种格式的已执行查询数、有结果的事件数、精确命中数、人工相关比例和费用。未完成查询不能当成零命中，规则命中也不能替代人工准确率。交给站长后再定生产格式。
