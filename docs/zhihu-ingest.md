# 知乎讨论接入 PsyHOT

首次试接：2026-10-14。定位：与 Bluesky 学者讨论共用 `hot_signal` 路径，提供独立关注证据；不直接进入精选或日报，不按赞数增加事件质量。

## 接入流程

MediaCrawler 知乎搜索 → contents JSONL → 知乎字段转换与引用保留 → 外部材料入库 → 事件归组 → 已有研究的热度证据。

第一版使用 `scripts/import-zhihu.ts`。默认只转换和预览；加 `--import` 才在 `DATABASE_URL` 指定的数据库中注册来源并导入。注册和接收使用同一个数据库，避免来源建在本机、内容却发到另一台服务器后被隔离的问题。

该命令复用外部接口底层的 `ingestItems`、统一材料入口和任务队列，没有新建一套评分、归组或发布流程。HTTP 外部接口也已增加可选 `bodyText`、`excerpt`、`language`，其他调用者仍可沿用原格式。

## 信号规则

- 每个匿名化创作者对应一个 `mc-zhihu-<creator_hash>` 来源，参与方式为 `hot_signal`，与 Bluesky 使用同一类事件证据。
- 来源为 `external`、T2、非一手；站内和分发全文开关均关闭。档位不把帖子变成论文证据，热度只表示关注。
- 正文中的链接、HTML 中的引用链接和 `content_links` 都会保留；知乎跳转链接还原为 HTTP(S) 原地址，去掉跟踪参数，不读取这些地址来补写内容。
- 正文有论文 URL 或 DOI 时可直接关联已收录事件。一般语义关联仍由现有 worker 的向量和归组流程处理，是否调用模型遵循 worker 的开关与预算。
- 同一来源在同一事件窗口内仍只按一个独立参与方计算。已知属于同一机构或同一人的跨平台来源，需要在后台设置相同的 `signal_group_id`；匿名哈希不能自动证明跨平台身份。
- 只处理回答与文章。视频、无可用文本、缺少创作者哈希或合法发布时间的记录会跳过。
- 来源创建后名称暂用哈希短标签；确认机构或作者来源后，可在后台改为适当的显示名称。

## 数据完整性

- 按 `content_type + content_id` 合并一次导出中的重复记录。不同更新时间选较新版本；同版本保留更完整的正文并合并引用，引用 URL 的长度不参与正文完整度比较。
- 去掉帖子链接的跟踪参数和片段；回答的 `question_id` 必须与 URL 一致；拒绝带用户凭据或非标准端口的内容 URL。
- 同一回答 ID 在一个导出中出现冲突 URL，会在任何导入前报错。实际导入也会检查已有知乎记录，避免后续导出给同一个回答建立不同地址。
- 重复导入相同材料不会创建新条目或新内容版本。纯互动统计不进入正文版本判断。
- 原始发布时间决定时间线。发现时已经超过 48 小时的内容按历史归档，不增加当前事件热度，不进入今天的推送。
- 原始导出保留在本地 `.data/`，转换输出只包含必要的内容与来源信息，不带 Cookie、原始作者 ID、访问令牌或个人资料。

## 操作

在 `AIHOT/` 目录执行：

```bash
# 使用相邻 MediaCrawler 的项目虚拟环境试抓，每个关键词一页，不抓评论或媒体。
../MediaCrawler/.venv/bin/python tools/zhihu-trial.py

# 预览转换结果；这是默认模式，不写数据库。
node scripts/import-zhihu.ts \
  --input .data/zhihu-trial/zhihu/jsonl/search_contents_2026-10-14.jsonl \
  --output .data/zhihu-trial/import-preview.json

# 先人工选择用于试验的条目，再明确导入当前配置数据库。
COLLECT_ENABLED=false MODEL_CALLS_ENABLED=false \
node --env-file=.env scripts/import-zhihu.ts \
  --input .data/zhihu-trial/trial-contents.jsonl --import
```

日期文件名来自 MediaCrawler 实际输出。`--backfill` 可以显式标记历史回灌。命令行开关只作用于该命令；如果另有 worker 正在运行，它按自己的模型、推送及预算设置处理队列。本次本地网站没有启动 worker。

试抓工具使用独立浏览器配置，不连接用户其他已打开的浏览器。首次登录由用户用知乎 App 扫码完成，后续复用该配置的登录态；遇到访问限制应停止，不通过代理切换或升级重试。

## 2026-10-14 真实试接结果

两轮各三个关键词，每个词一页：

| 第一轮 | 记录数 | 第二轮 | 记录数 |
|---|---:|---|---:|
| 心理学 论文 | 18 | 心理学 Nature | 17 |
| 心理治疗 研究 | 17 | 心理治疗 元分析 | 18 |
| 人工智能 心理健康 | 18 | AI 心理健康 研究 | 18 |

- 原始记录 106 条，转换去重后 98 条。
- 23 条原始记录含转换器可识别的引用链接；原始结构化 `content_links` 非空的为 21 条，另有文本中的 URL。
- 试抓时 7 条记录发表于最近 48 小时。搜索结果也包含论文作业、机构推广和教程，关键词搜索尚不能替代信源评估。
- 对照本地 440 条已有研究／事件报道，引用没有直接命中已收录事件；这个检查针对链接／DOI，不代表模型语义匹配一定为零，也不代表线上库覆盖相同。
- 从结果中选择 3 条带引用、与心理学相关的讨论做本地导入试验，注册 3 个 `hot_signal` 来源。正文分别为 4,426、3,503、9,901 字符，均已完整进入材料表。
- 3 条发布时间分别为 2026-09-21、2026-06-25、2024-10-05，全部按历史规则处理，归组结果 `historical`。本次实际新增热度证据 0 条，独立公开内容 0 条。
- 首次重复导入返回 `created: 0`，当时各条内容版本均为 1。最终确定性合并规则调整了第一条内容的引用排列，系统如实记录为第 2 版；另外两条仍为第 1 版。2026-10-14 再次核验已完成该修订的历史处理，3 条均为 `skipped`、历史回灌且不进入公开内容列表。

真实结果说明采集、引用保留、转换、注册、入库、历史处理和重放已经工作。新增事件热度的路径通过独立测试样例验证：同一论文的知乎和 Bluesky 讨论各产生 `kind=signal` 的独立参与方证据，直接链接关联不调用模型。

接下来应围绕站内已经追踪的具体研究标题、作者和论文关键词发现讨论，再评估稳定账号，而不是把本次搜索出的全部账号设为长期采集来源。本次没有建立常驻抓取计划，也未部署到线上站点。
